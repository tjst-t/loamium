## タイミング安定化の対応

固定 sleep の代わりにポーリング (pollUntil) を採用。
debounceMs=300ms (テスト用短縮) + timeoutMs=10s のポーリングで安定。
オフラインキューテスト: pollUntil で offline=true AND queued>=1 を同時確認。

## 実装上の重要な発見

1. git status --porcelain=v2 の branch.ab: git push --set-upstream なし (デフォルト push)
   の場合はトラッキングブランチが設定されないため branch.ab が出力されず ahead=0 になる。
   → #countAheadRevs() で git rev-list HEAD ^origin/main を fallback として実装。
   → push 後も origin/main リモート ref は .git/refs/remotes/ に残るため
     リモート URL 変更後も rev-list でカウントできる (実証済み)。

2. syncNow() と autoSyncOnce() のリトライ可能エラー検出を両方で実装する必要あり。
   テストが POST /api/sync/now を使用するため syncNow() にも isRetryableRemoteError チェックを追加。

## スコープ外知見と懸念事項

- out_of_scope_findings: なし
- concerns:
  - SyncScheduler の start() は server boot 後に呼ばれるが、設定変更 (PUT /api/sync/config) で
    pullIntervalMs が変わっても既存インターバルは更新されない。設定変更後はサーバー再起動が必要。
    Story 4/5 の UI 要件次第では動的更新の対応を追加すること。
  - flush() で server.stop() が呼ばれると autoSyncOnce() が途中で abort される可能性。
    Node.js プロセス終了まで 2000ms のタイムアウトがあるため大部分は完了するが保証はない。
