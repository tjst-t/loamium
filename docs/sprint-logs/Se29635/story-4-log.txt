## Escalations / Judgment Calls
1. ConflictResolverDialog reuse: The git-level conflict uses the same dialog component. However
   the "save" callback for git conflicts is currently a thin wrapper (marks conflict as resolved
   visually, re-fetches status). Actual writing of resolved text to vault + re-push is left as
   a future enhancement since the AC only requires "surface unresolvable hunks via dialog".
   Local edits are NOT lost (git rebase --abort preserves them).

2. status().conflicted uses #conflicted (engine flag) rather than git status 'u' lines.
   This ensures the conflict badge persists until the next successful pull/sync, even after
   rebase --abort restores the working tree (which would clear the 'u' status lines).

3. Focus listener guards: Only fires when status.available && status.remoteConfigured to
   avoid spurious API calls when sync is not configured.
